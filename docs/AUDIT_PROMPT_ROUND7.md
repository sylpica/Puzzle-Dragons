# パズドラ練習アプリ品質監査（ラウンド7）のお願い

あなたは品質監査の専門家です。添付の `index.html`（パズル＆ドラゴンズの盤面練習用・単一ファイルWebアプリ）を監査してください。

## 成果物の形式（厳守）
- 報告書と証跡は、必ず**生成ファイル**として出力してください（ファイル名に `ROUND7` を含めること。例: `ROUND7_AUDIT_REPORT.md`、`ROUND7_EVIDENCE.json`）。チャット本文への長文転記は不要です。
- 報告書の冒頭に、対象ファイルの行数と、本指示書の検証項目見出し（U1〜U5）を復唱してください。
- 各指摘には必ず「再現手順」「実在するコード箇所（関数名・行の内容）」「実測値」を付けてください。実在しない関数名・要素IDを根拠にした指摘、実測していない数値は無効です。
- 問題がなかった項目は、試行規模（回数・盤面数など）を添えて「実測のうえ問題なし」と書いてください。
- 検証できなかった項目は「未検証（理由）」と明記してください。推測で補わないでください。
- 修正提案は、実在する関数に対する差分形式（変更前／変更後のコード断片）でのみ提示してください。

## 意図的な仕様（欠陥として扱わないこと）
- コンボは1コンボずつ順に発生する（同時判定しない）。演出は1コンボあたり約250ms。
- 落ちコンなしが基本: 消去で空いたマスはターン中は空白のまま、新ドロップは落ちてこない。既存ドロップの落としによるコンボは成立する。盤面のコンボ終了時に空マスへ補充し、その補充ではコンボは成立しない。
- 操作時間の初期値は6.0秒（本家の現行仕様）。
- ルーレットは全マス共通のグローバルクロックで同期し、操作中も回り続ける（掴んでいるマスとロックされたドロップは凍結）。解決中は位相をラッチする。全マスが同じルーレットの盤面ではシャッフル後もマッチが残りうる（仕様メモに明記済み）。
- ロック解除はL字消しの簡略ルール（L字の角にあたるセルを含むマッチで盤面全体のロックを解除。T字・十字は不可）。
- 3個以上繋がった爆弾は他の爆弾の爆発に巻き込まれない（保護される）。
- 目覚め「多め」の出現率はマッチ回避の仕組みのため実測約33%（公称3/8とは異なる）のが正常。
- 保存機能は廃止済み（存在しないのが正常）。ページズームは全面禁止が仕様。
- 消せないは属性単位で選ぶ仕様（ドロップ単位のフラグは存在しないのが正常）。属性判定は現在の実効タイプ（ルーレット表示色を含む）に対して行う。
- 目覚めの特殊効果（お邪魔・毒・猛毒・トゲ・超暗闇）は個別トグル式で、併用できるのが仕様。本家の落下率は非公表のため、割合はアプリ独自設定。
- パーティ・敵・HPゲージ・勝敗判定は未実装が仕様（ダメージは最大HP比%表示のみ）。

## 検証項目

### U1 消せない属性の全経路
- 消せない属性のドロップは、横・縦・L字・十字などのどの形でもマッチ判定から除外され、コンボ数にも入らないか。他属性のマッチは通常どおり消えるか。
- ルーレット表示色が消せない属性になっている間だけ消えないこと（表示色が変われば消えるようになること）、逆も同様か。
- 消せない属性のドロップが爆弾・毒など特殊ドロップと組み合わさった場合の扱いに矛盾はないか（例: 消せない属性のお邪魔は通常のお邪魔として扱われるか）。
- 全状態クリア・全リセット・元に戻す（スナップショット）での消せない属性の保持／初期化が、それぞれの操作の意味と一致するか。
- 🚫バッジの表示が、実効タイプ基準で正しく追従するか（ルーレットで色が変わった瞬間）。

### U2 特殊目覚め（個別トグル）の相互作用
- 各トグル単独ON時の補充プール構成と実測出現率が、実装上の重み付けと一致するか（お邪魔・毒・猛毒は各タイプが落ちやすくなる／トゲは補充ドロップの一部に付く／超暗闇は補充ドロップに超暗闇が付く）。
- 複数トグルの同時ONで、プール構成が意図どおり合成されるか。お邪魔と毒など種別の混入（ONにしていない種別が出る）がないか。
- 目覚め本体（多め／のみ）と特殊目覚めの併用時、プールが正しく合成されるか。「のみ」の純度が特殊目覚め以外で破れていないか。
- シャッフル経路でも特殊目覚め（トゲ・超暗闇）が補充と同じ規則で付くか。
- 全リセットで全トグルがOFFに戻り、「のみ」の色選択が初期（火・水）に戻るか。

### U3 「のみ」2〜4色カスタムの境界と状態の切り分け
- チェック操作で2色未満・5色以上にできないこと（UI操作・プログラム的変更の両面）。
- 3色・4色選択時の補充純度（選んだ色以外は落ちない）と、落ちコンなし補充の範囲外フォールバック頻度。
- 「のみ」選択状態が、盤面サイズ変更・編集モード往復・シャッフル・元に戻すでどう扱われるか（保持されるべき場面で保持され、初期化されるべき場面＝全リセットでのみ初期化されるか）。
- 目覚めセレクトを「のみ」以外に変えたとき、カスタム領域の表示と内部状態が矛盾しないか。

### U4 ラウンド6修正の再検証と副作用
- 編集の3経路（ドロップのペイント配置・一括変更・陣）すべてで、ルーレットマスへの特殊ドロップ配置が火に変換されるか。ロックされたドロップは変換されないこと（従来仕様）。
- 全リセットでルーレット設定（プリセット・色・間隔）が初期化されること。逆に、パレット再描画だけでは保持されること（保持と初期化の切り分け）。
- lostpointercapture 相当のキャプチャ喪失時に掴み状態が残らないこと。通常の pointerup 経路が二重に解決処理を走らせないこと。
- 320px幅（およびそれ以下）でヘッダー・ステータスに横はみ出しがないこと。横向き（844×390、812×375、640×360）でステージ内スクロールにより全操作に到達できること。縦向き375px級で従来の見た目・到達性が劣化していないこと。

### U5 状態ライフサイクルの整合性（保持／初期化マトリクス）
以下の一覧表を作り、各セルを実測で埋めてください（対象の状態 × 操作 → 保持される/初期化される/対象外）:
- 状態: 盤面サイズ、操作時間、落ちコン設定、目覚め本体、特殊目覚めトグル、「のみ」色選択、消せない属性、ルーレット設定（プリセット・色・間隔）、ターン/コンボ/被ダメ記録、アンドゥ可否
- 操作: 全リセット、記録リセット、盤面リセット（編集タブ）、シャッフル、盤面サイズ変更、編集モード往復（編集なし）、編集モード往復（配置あり）、元に戻す、全状態クリア
- 表の結果と、各操作の名前・説明文（title属性）からユーザーが受ける印象との食い違いがあれば指摘してください。

## 重点の置き方
