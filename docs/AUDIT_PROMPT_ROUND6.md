# パズドラ練習アプリ 品質監査プロンプト（ラウンド6：環境差異・長時間・極端条件）

## 目的
ラウンド1〜5は要件適合・実機忠実度・統計・不変条件を監査した。ラウンド6は新しい角度として、**実行環境の差異、長時間セッション、極端な設定値の隅**を監査する。短時間の正常系では現れない劣化・リーク・環境依存の破綻を探すこと。

## 対象と前提
- index.html（単一ファイルの静的アプリ。パズル練習専用で、パーティ編成・敵・HPゲージ・勝敗判定は意図的に存在しない。これらの不在を指摘しないこと）
- 意図的仕様（指摘対象外）：コンボは1コンボずつ逐次処理／ロック解除はL字の簡略ルール／ルーレットは解決中は位相ラッチ／保存機能なし／ズームロック／基本操作時間6.0秒／落ちコンなし＝ターンの間は空白・ターン末に一度だけ補充・その補充ではコンボ不成立／多めプロファイルの出現率がマッチ回避のため約33%になること（実測済み・仕様として確定）
- ラウンド5で修正済みの4件（2色シャッフルの未解決マッチ、解決中のactivePid残留、特殊ドロップのルーレット進入時火変換、ルーレットカスタム設定の保持）は T4 で再検証する。

## 検証項目
### T1 実ブラウザ差異
ポインターイベントの暗黙キャプチャ、iOS Safari / Android Chrome での 100dvh とアドレスバー伸縮時の盤面フィット、タッチ操作とページスクロールの競合（touch-action の効き）、ダブルタップや長押しの誤作動。ヘッドレス環境で再現できない項目は、推測で「問題なし」とせず「未検証（理由）」と明記すること。

### T2 長時間セッションの劣化
連続300ターン相当の操作（ドラッグ解決・シャッフル・編集・リセット混在）を通し、以下を監視する。
- 状態ドリフト：ターン／コンボ／最大コンボ／被ダメ表示が内部状態とずれ続けないか
- リーク：DOMノード数の単調増加、setInterval の多重起動、イベントリスナーの重複、phaseLatch 等の一時状態の残留
- 盤面・pos 配列の整合性（サイズ変更を繰り返した後に次元が崩れないか）

### T3 極端な設定の隅
操作時間1.0秒と200秒の両端、7×6盤面に全ギミック同時配置（雲・テープ・ルーレット全マス、ロック・トゲ・暗闇・超暗闇の重ね掛け）、超暗闇カウンタの境界、盤面サイズ変更直後のアンドゥ、編集↔プレイ往復の連打、解決中のサイズ変更試行。これらで例外・状態破壊・表示崩れが出ないこと。

### T4 ラウンド5修正の再検証と副作用
- シャッフル：全プロファイルで完成盤面がマッチなし、2色の純度維持。あわせて修正後のシャッフル分布が修正前と大きく変わっていないか（多め色の比率など）。
- チェッカーボード・フォールバックに実運用で到達し得るか（到達するなら頻度と見た目）。
- パレット再描画でルーレット設定（プリセット／色／間隔）が保持されること。設定リセットでは初期化されること（保持と初期化の切り分け）。
- ルーレット進入変換：ドラッグ・落下・編集配置の各経路で特殊ドロップが火になること。変換が全セル同期やロック凍結を壊していないこと。
- pointerdown の判定順序変更が、通常のドラッグ開始・テープマスの拒否・編集モードの描画に影響していないこと。

### T5 表示の隅
幅320px・375px、横向き、文字が切れる／はみ出す箇所、コンボポップとタイマーバーの重なり、ボタン・ピルの折返し。実測（スクリーンショットまたは寸法）に基づいて述べること。

## 出力形式（厳守）
- **報告書と実測データは生成ファイル（Markdown＋JSON等の証跡）として残すこと。** チャット本文は要約のみでよい（ラウンド5でチャット本文と生成ファイルの内容が食い違う事例があったため、生成ファイルを正とする）。
- 指摘ごとに「再現手順」「実測値または実在するコード箇所」「根拠」をセットで示す。
- 実在しない関数名・変数名を書かないこと。計測していない数値・試行回数を書かないこと。実行していない検証を「実測」と書かないこと（コード読解のみの場合はそう明記する）。
- 修正コードを提示する場合は、実在する関数に対する差分形式のみ可。全体ファイルの再生成は不要。
- 意図的仕様（上記）に抵触する修正は提案しない。
- 問題が見つからなかった項目は「実測のうえ問題なし」と試行規模を添えて明記する。
