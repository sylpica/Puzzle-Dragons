# 品質監査レポート（第1回・汎用監査プロンプト適用）

- 監査対象: sylpica/Puzzle-Dragons（パズル練習アプリ、単一ファイル静的Webアプリ）
- 監査開始時点のコミット: main `1c7e49f` / 公開URL https://sylpica.github.io/Puzzle-Dragons/
- 監査日: 2026-11-05
- 監査方法: 静的解析（全コード精読）＋ Playwright（headless Chromium）による実操作・異常系・境界値テスト＋ 修正前後比較
- 総合判定: **検証範囲内で合格**（Critical/High の未解決事項なし。下記「未解決事項」の制約つき）

| 要求 | 実装 | 検証 |

## B. 発見した問題と修正

深刻度: P1=High / P2=Medium / P3=Low。全件「修正前に失敗を再現 → 修正 → 再検証で解消」を実施。

| ID | 深刻度 | 問題 | 根本原因 | 修正 |
|---|---|---|---|---|
| F-01 | P2 | localStorage の保存データが破損していると起動時に例外が発生し、初期化が中断する | `JSON.parse` が4箇所で無防備に呼ばれていた | `parseSaves()` で一元的に保護（破損時は空として扱う） |
| F-02 | P1 | 盤面コード読込・保存盤面の読込で、不正なデータ（未知のドロップ種・非対応サイズ・欠損フィールド）を受け入れ、描画が崩壊する | 外部由来データの検証が皆無だった | `sanitizeData()` を新設：サイズ許可リスト、型ホワイトリスト、数値クランプ、uid再割当、ルーレット色/間隔の検証。不正データは拒否して通知 |
| F-03 | P2 | 盤面サイズ変更後にアンドゥすると、旧サイズの盤面が新サイズの状態へ復元され描画が壊れる | スナップショットにサイズ情報がなく、サイズ変更で無効化もされていなかった | スナップショットに cols/rows を含め復元時に検証＋サイズチップ追随。サイズ変更・シャッフル・一括操作・読込でスナップショットを無効化 |
| F-04 | P2 | マルチタッチ時、2本目の指の移動で掴んだドロップが動く／2本目の指を離すと操作が終了する | ポインターIDの識別をしていなかった | `activePid` で操作中ポインターを固定し、他ポインターの move/up/cancel を無視 |
| F-05 | P3 | 「目覚め」補充に超暗闇が混ざるが、UIラベル（毒・お邪魔・トゲ）に記載がなく仕様と表示が不一致 | 補充処理への混入実装がラベルに反映されていなかった | 超暗闇の補充混入を削除し、ラベルどおりの挙動に統一 |
| F-06 | P3 | 操作中に操作時間を変更すると、残り時間の計算が途中で変わる | タイマーが `opTime` を毎tick参照していた | 操作開始時点の制限時間をクロージャに固定 |
| F-07 | P3 | 補充マッチ回避チェックで、上方向だけ実効タイプ（ルーレット色）でなく素のタイプを見ており判定が非対称 | 実装の不統一 | 上方向も `effType` に統一 |
| F-08 | P3 | 編集モードで速くドラッグすると間のマスが塗り飛ばされる | pointermove の到達マスしか塗っていなかった | 前回マスからの経路補間で全マスを塗る |
| F-09 | P3 | 保存時にストレージ容量不足などで例外が出ると無言で失敗する | `setItem` が無防備だった | try/catch し、失敗時はユーザーへ通知 |

### テスト側の欠陥（アプリでなく検証ハーネス側）も3件発見・修正
- T-A: スライド判定が inline style（即時反映される目標値）を読んでおり、実際は滑らかに動いているのに失敗扱いになっていた → computed style の実測に修正し、軌跡（114.6→96.1→80.8→69.3→62.5px）で滑らかさを確認
- T-B: 結果表示テストの期待値が、仕込んだ盤面の実際の合体結果（火4個）とずれていた → 盤面の真実に合わせて期待値を修正
- T-C: ドロップ数セレクタ誤り（`.drop`→`.dnode`）と、確率事象の標本不足 → セレクタ修正＋30回反復標本に強化

## D. UI/UX 検証範囲
- 検証端末幅: 375 / 390（headless）。盤面下端フラッシュ、編集ツールが盤面上部に収まりスクロール不要であることを実測。

## E. セキュリティ所見
- 外部通信なし・認証なし・個人データなし。innerHTML の挿入元は内部定数（タイプ名・数値）のみで、ユーザー入力（保存名）は textContent/value 経由のみ。盤面コード・保存データは sanitizeData 経由に統一済み。残存は開発者ツール経由の自己XSS相当のみで、実害範囲は本人のブラウザ内に閉じる。

## F. 未解決事項・制約
1. 実機（iOS Safari等）での最終確認は未実施（環境制約）。公開環境での動作は配信後に取得確認する。
2. アクセシビリティはボタン要素・ラベルの基本確認までで、WCAG 2.2 AA の網羅監査は未実施（本アプリは色＋グリフ併用表示のため色単独依存ではない、という確認まで）。
3. L字消しでのロック全解除は、本アプリの簡略ルールとしてフッターに明記済み（本家の厳密仕様とは異なる割り切り）。
4. CI は存在しない（単一ファイル静的サイトのため、検証は本監査のローカルスイートで代替）。
