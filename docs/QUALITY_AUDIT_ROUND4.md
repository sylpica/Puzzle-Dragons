- 実施体制: Muse側監査・修正 → ChatGPT（推論 High、新規チャット）クロス監査・修正コード提示 → 全指摘を実リポジトリと照合してから採否判定（ユーザー指示の収束ループ）

## 1. Muse側で発見・修正した欠陥（GPT結果に先行して検証）

### D1. L字判定の緩さ（ロック解除条件）
- 旧実装: 消去グループ内に「横3つ以上のラン」と「縦3つ以上のラン」が両方あればL字とみなしていたため、**T字・十字の消去でも全ロックが解除**されていた。
- 修正: 厳密な角判定に変更。グループ内のセルが、横ランと縦ランの**両方の端**に位置する場合のみL字成立とする。
- 回帰テスト: L1（T字→解除されない）、L2（十字→解除されない）、L3（真のL字→解除される）、L4（例外なし）— 全て合格。

### D2. ドラッグ中のUI競合
- 旧実装: 盤面サイズ変更チップにドラッグ中ガードがなく、ドラッグ中の2本目タップで盤面が差し替わり、保持ドロップの範囲外アクセスで例外・状態破壊が起こり得た。設定リセットは動作中タイマーを止めていなかった。
- 修正: サイズ変更／シャッフル／アンドゥ／被ダメリセットをドラッグ中はブロック（サイズ変更はスナップショットも破棄）。設定リセット・状態リセットはドラッグ状態（held／heldUid／moveStarted／activePid／lastPointer）を完全キャンセルし stopTimer() を呼ぶ。
- 回帰テスト: V1（ドラッグ中サイズ変更ブロック、手番は正常に解決）、V2（ドラッグ中リセットで held=null・timer=null・turn=0・表示6.0）— 全て合格。

## 2. ChatGPT指摘の検証結果

### 採用・対応済み
- **#1（R16 落ちコンなし）**: 旧版に対しては正しい指摘。ただしユーザーの定義訂正（2026-11-05 18:33「ターンが終わるまで空白になったマスができること」）を受け、現行版では既に再設計済み：ターンの間は消去マスを空白のまま保持（落としのみ発生）、全コンボ終了後に一度だけ補充、その補充ではコンボが成立しない。GPTのR16再監査・修正案も同じ結論に到達した。現行版への追加対応は不要。
- GPTが初期回答で挙げた重大領域のうち「特殊消去（非L字でのロック解除）」「操作の安全性（盤面変更・リセットのタイミング）」は、上記 D1／D2 として実在を先行確認し修正済み。

### 不採用（検証の結果、実在しない・要件外）
- **#2〜#24の大半**: パーティ編成・敵の攻撃／属性・勝利条件・回復力計算など、**本アプリに存在しない機能**への指摘。アプリはパズル練習専用で、これらは要件 R1〜R33 の範囲外。GPT自身の一覧表でも対応する要件番号は全て「問題なし」とされており、指摘本文と自己矛盾している。再現手順・実コード箇所の裏付けもない。
- **#13の統計主張**（火多め3,000盤面の実測で火31.1%、抽選元の37.5%より低い）: 計測方法・再現手段の提示がなく**未検証**として扱う。なお偏りの機構自体（マッチ回避リロールは出現率の高い色を相対的に弾きやすい）は実在するため、ラウンド5の検証項目 S1（分布統計）で実測する。現行の回帰テスト O4（水多め3,000盤面相当）では出現率0.32〜0.44の許容範囲内。
- **GPT修正コード**: チャットで提示された差分は、実在しない関数（dropAndRefill／fillTop／clearCombo／clearBomb／randomDropAvoiding 等）や6×5固定の盤面モデルを前提としたもので、実コードには適用不能。
- **GPT統合修正版ファイル（998行）の実測判定**: 旧版コードを元にした再生成物だったため、現行の回帰スイート44項目をそのまま流して判定した。結果は **2件失敗**：
  - O1失敗：落ちコンなし補充200盤面中**120盤面でマッチが発生**（現行版は0盤面）。GPT版の補充はマッチ回避が効いていない。
  - V1失敗：ドラッグ中のサイズ変更がブロックされず盤面が7×6に差し替わる（D2の修正を含まない旧版ベースのため）。
  - よってGPT統合版は現行版より品質が低く、**一切採用しない**。

## 3. ファズによる実証（GPT指摘 R16-2「ターン末補充でコンボが成立する」への反証）

GPTの再監査は「ターン末補充のコンボ成立チェックが誤っている」と主張したため、現行版に対して実測で反証した。回帰スイートに FZ セクションを追加：

- 条件：落ちコンなし × 目覚めプロファイル5種（なし／毒・お邪魔・トゲ／水多め／火・水のみ／光・闇のみ）
- 方法：各プロファイルで「横3つ揃い×2組＋爆弾1個」を植えた盤面を12回、resolveBoard() で完全解決
- 結果：**全60解決で、静止時の盤面は完全（空きマスなし）かつマッチ0件**。例外もなし。スイート全体は54項目・失敗0。
- 静的裏付け：spawnCell のマッチ回避は、あるマスに対して成立し得る色が高々4色（横軸・縦軸で各最大2色）しかないため、BASIC 6色の中に必ず回避色が存在し、フォールバックで必ずマッチ不成立が保証される構造であることもコード上で確認した。
