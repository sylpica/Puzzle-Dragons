# パズドラ練習アプリ 「元に戻す」機能 監査プロンプト

## 目的
「元に戻す」ボタンが、**直近にドロップを動かす直前の盤面状態へ正確に戻る**ことを監査する。対象は index.html（単一ファイルの静的アプリ、パズル練習専用）。

## 仕様（あるべき姿）
1. ドロップを実際に動かした（1回以上入れ替えた）あと、解決が終わってから「元に戻す」を押すと、動かす直前の盤面（ドロップ種・状態異常・位置ギミック）と、ターン／コンボ／被ダメ等の表示が復元される。
2. 動かさなかったタップ（押して離しただけ）は、元に戻すの対象を消費しない。
3. 編集モードを開いて閉じただけ（盤面を変更していない）では、元に戻すの対象は消えない。編集で盤面を変更したら対象は消える。
4. 元に戻すは1手分だけ。2回押してもそれ以上は戻らない。対象が無いときは何も起きない。
5. 解決中・ドラッグ中は元に戻せない。
6. 時間切れで手が終わった場合も、指を離して終わった場合と同じく元に戻せる。
7. シャッフル・盤面サイズ変更・一括変更・各種リセットなど、盤面や状態を作り直す操作をしたら、古い対象では戻せない。
8. 2手続けて動かした場合、元に戻すで戻るのは2手目の直前（1手目の結果）であり、初期盤面ではない。

## 検証してほしい観点
- 上記1〜8がコードと実測の両方で成立するか。特に snapshot の保存・確定・破棄のタイミング（ポインターダウン／初回入れ替え／指離し／タイマー満了／モード切替／各種ボタン）。
- 復元が「盤面の見た目」だけでなく内部状態（ターン、最大コンボ、被ダメ、直近結果表示、ルーレットやロック等の状態）まで一致するか。
- 復元後にそのまま次の手を正常に打てるか（ドラッグ、タイマー、解決、再度の元に戻す）。
- 例外や不整合が出る操作順序がないか（ファズ的に操作を混ぜて確認してほしい）。

## 出力形式（厳守）
- **報告書と実測データは生成ファイル（ダウンロード可能なMarkdown＋証跡ファイル）として残すこと。ファイル名には UNDO を含めること。** チャット本文は要約のみでよい。
- 冒頭で「対象ファイルの行数」と「仕様は8項目」と復唱すること。
- 指摘ごとに「再現手順」「実測値または実在するコード箇所」「根拠」をセットで示すこと。
- 実在しない関数名・変数名を書かないこと。計測していない数値を書かないこと。実行していない検証を「実測」と書かないこと。
- 修正コードを提示する場合は、実在する関数に対する差分形式のみ可。
- 問題が見つからなかった項目は「実測のうえ問題なし」と試行規模を添えて明記すること。
