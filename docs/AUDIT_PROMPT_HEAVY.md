# パズドラ練習アプリ品質監査（使い倒し編）のお願い

あなたは品質監査の専門家であり、同時にパズル＆ドラゴンズのヘビープレイヤーです。添付の `index.html`（パズドラの盤面練習用・単一ファイルWebアプリ）を、**毎日このアプリで30分以上練習するヘビーユーザーの視点**で監査してください。コードを読むだけの監査ではなく、実際にブラウザで操作を繰り返して、不具合と使いにくさを掘り出してください。

## 成果物の形式（厳守）
- 報告書と証跡は、必ず**生成ファイル**として出力してください（ファイル名に `HEAVY` を含めること。例: `HEAVY_AUDIT_REPORT.md`、`HEAVY_EVIDENCE.json`）。チャット本文への長文転記は不要です。
- 報告書の冒頭に、対象ファイルの行数を復唱してください。
- 結果は次の2区分に分けてください:
  - **不具合**: 実測で確認した誤動作・フリーズ・状態破壊・表示と実態の不一致。各件に「再現手順（実際の操作列）」「実在するコード箇所」「実測値」を必ず付けること。実在しない関数名・要素IDを根拠にした指摘、実測していない数値は無効。
  - **使い倒し視点の提案**: 不具合ではないが、繰り返し使うと効いてくる摩擦・非効率・誤操作リスクへの改善提案。各件に「その操作を繰り返したときの実測（タップ数・所要時間・発生頻度など）」と「期待できる改善」を付けること。感想だけの提案は無効。
- 問題がなかった項目は、試行規模を添えて「実測のうえ問題なし」と書いてください。
- 検証できなかった項目は「未検証（理由）」と明記してください。推測で補わないでください。
- 要約表と詳細で数値を食い違わせないでください。

## 意図的な仕様（不具合として扱わないこと。提案として触れる場合は、その旨を明記すること）
- 盤面の保存・コード出力機能は、利用者の明示的な決定で廃止済み（存在しないのが正常）。
- コンボは1コンボずつ順に発生する。演出は1コンボあたり約250ms。操作時間の初期値は6.0秒。
- 落ちコンなしが基本（消去マスはターン中空白、補充はコンボ終了時に1回、その補充ではコンボ不成立）。落ちコンありも選べる。
- ルーレットは全マス共通のグローバルクロックで同期し、操作中も回り続ける（掴んだマスとロックは凍結）。解決中は位相ラッチ。ルーレットのマスだけで同じマッチが繰り返される場合とコンボ99回到達時は、フリーズ防止のため解決を打ち切るフェイルセーフがある。
- 超暗闇は補充の約30%に残り1ターンで付き、落ちたターンの解決では減らず次のターンの解決末に0になる。目覚め「のみ」は絶対（選んだ2〜4色だけが落ちる。特殊目覚めのお邪魔・毒・猛毒は混ざらない）。目覚め「多め」の出現率は実測約33%が正常。
- 消せないは属性単位。選択は盤面リセット・サイズ変更では保持され、全リセットと全状態クリアでのみ初期化される。
- ロック解除はL字消しの簡略ルール。3個以上繋がった爆弾は他の爆弾の爆発に巻き込まれない。毒（個数+1）×5%、猛毒（個数+1）×12.5%、爆弾20%、トゲ1マス4%。
- ドラッグ中、掴んだドロップは盤面の外に出ないようクランプされる。ページズームは全面禁止。体力ゲージは付けない（ダメージは%表示のみ）。
- パーティ・敵・勝敗判定は未実装が仕様。

## やってほしい操作（最低限。ここから先は自由に増やしてよい）
### H1 実ポインタでのドラッグ酷使
- 通常のドラッグを多数（30回以上、ランダムな経路・長さ・速度で）。
- 乱暴な操作: 画面外へのはみ出し、超高速の往復、ジグザグ、同じ2マスの連続往復、指を離す直前の急反転。
- 割り込み: 解決中のドラッグ試行、ドラッグ中のモード切替・サイズ変更・各種リセット・シャッフル、ドラッグ中のリサイズ/回転、ポインタキャンセル相当の操作、2本指タッチ。
- 各操作の後に、盤面が満杯で全ドロップが有効な種別であること、掴みっぱなしや解決中フラグの残留がないことを確認すること。

### H2 繰り返し操作と連打
- シャッフル・アンドゥ・各リセット・サイズ切替・モード開閉の連打（10回以上を高速で）。
- 同じ設定の作り直しを繰り返す（例: ルーレット3マス盤面を5回作り直し、全工程のタップ数と所要時間を毎回記録）。
- 練習サイクル（シャッフル→1手ドラッグ→解決完了）を15回以上繰り返し、1サイクルの所要時間の分布を記録。

### H3 長時間セッション
- 1,000操作以上の混合操作列（ドラッグ・編集・リセット・アンドゥ・サイズ変更・モード往復）を1セッションで実行し、開始時と終了時で同じ1コンボ解決の所要時間を比べるなど、性能劣化・メモリ増加・例外・状態不整合がないか確認すること。

### H4 設定と再訪
- 操作時間・目覚め・特殊目覚め・消せない・盤面サイズ・ルーレット設定を一通り変えた後にページを再読み込みし、何が残り何が初期化されるかを全項目で記録すること（設定の保持は現仕様では未実装のはず。その事実確認と、ヘビーユーザー影響の評価を「提案」側に書くこと）。
- 誤タップの危険: 全リセット等の破壊的操作に確認があるか、隣接ボタンとの距離、取り返しのつかなさ（アンドゥで戻せるか）を実測すること。

### H5 操作効率の実測
- 375px幅で全タップ対象の実寸（高さ・幅）を測り、押しにくいものを列挙すること。
- よく使う操作までのタップ数: 新規盤面、記録リセット、被ダメリセット、目覚め変更、のみ色変更、特殊目覚め切替、編集で特定ギミックを置く、の各々。
- 操作時間タイマーの表示更新の細かさ（長い操作時間で残り時間が滑らかに減るか）。

## 重点の置き方
「正しく動くか」だけでなく「毎日使い倒すと何が起きるか・何がうんざりするか・どこで誤操作するか」を、実測で掘ってください。新規の不具合があれば遠慮なく挙げてください。提案は、不具合と混ぜず、実測の裏付けがあるものだけにしてください。
