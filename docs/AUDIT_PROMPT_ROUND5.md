# パズドラ練習アプリ 品質監査プロンプト（ラウンド5：統計・不変条件ファズ）

## 目的
ラウンド1〜4は要件適合（R1〜R33）と実機仕様への忠実度を監査した。ラウンド5は新しい角度として、**統計的性質**と**長時間ファズにおける不変条件**を監査する。単発の正常系確認ではなく、大量試行・ランダム操作・タイミング競合の下で性質が保たれるかを実測すること。

## 対象
- index.html（単一ファイルの静的アプリ。パズル練習専用で、パーティ編成・敵・HPゲージ・勝敗判定は意図的に存在しない。これらの不在を指摘しないこと）
- 前提とする意図的仕様（指摘対象外）：コンボは1コンボずつ逐次処理／ロック解除はL字の簡略ルール／ルーレットは解決中は位相ラッチ／保存機能なし／ズームロック／基本操作時間6.0秒（実機Ver.21.7準拠）／落ちコンなし＝ターンの間は空白のまま・ターン末に一度だけ補充・その補充ではコンボ不成立

## 検証項目
### S1 分布統計
各目覚めプロファイル（なし／毒・お邪魔・トゲ／各色多め／2色のみ）について、初期盤面生成と落ちコンなし時のターン末補充を大量試行（各3,000盤面以上）で計測し、色別出現率を抽選プールの理論比率と比較する。
- 乖離がある場合、それが「マッチ回避リロールによる系統的偏り」かどうかを切り分ける（偏りの方向と大きさを定量化する）。
- 欠陥と判定するのは、実害がある場合のみ：特定色が極端に枯れる、2色プロファイルで他色が混入する、毒・お邪魔の比率が公称（各20%）から大きく外れる等。
- 計測した試行数・実測値・理論値を必ずセットで示すこと。計測していない数値を書かないこと。

### S2 不変条件ファズ
ランダム盤面 × ランダム操作列（ドラッグ、編集モード切替、盤面サイズ変更、シャッフル、設定リセット、状態リセット、アンドゥ）を長時間連続実行し、以下を監視する。
- JavaScript例外が一切発生しない
- 解決完了後の盤面は常に完全（空きマスなし）
- 落ちコンなし時、静止状態の盤面にマッチが存在しない
- 状態表示（ターン／コンボ／最大コンボ／被ダメ%）が内部状態と矛盾しない
- アンドゥで復元される盤面・表示がスナップショット時点と一致する

### S3 競合・タイミング
- 解決処理中の追加タップ・ドラッグ・サイズ変更・各種リセットが状態を壊さない
- 操作タイマーの開始・停止がドラッグのライフサイクルと一致する（リセット後にタイマーが残らない等）
- タブの表示／非表示を挟んでもタイマーとルーレット時計が破綻しない（大きくずれる場合はその量を実測する）

### S4 ダメージ会計の突合
ランダムなギミック盤面で1ターンを解決し、被ダメ表示%を手計算と突合する。確定済みの式：毒（個数+1)×5%／猛毒（個数+1)×12.5%／未マッチ爆弾20%＋行列破壊／トゲ 移動1マス4%（保持ドロップ自身は免除）。合計の丸め（小数1桁表示）も確認する。

### S5 ルーレットの長時間挙動
全セル同期の色変化、保持中セルとロックドロップの凍結、解決中の位相ラッチを、0.5秒／1秒／2秒の各インターバルと色制限プリセット（カスタム含む）で検証する。お邪魔・毒・爆弾がルーレットマスに入った際の火変換とサイクル参加も対象。

## 出力形式（厳守）
- 指摘ごとに「再現手順」「実測値または実在するコード箇所」「根拠」をセットで示す。
- **実在しない関数名・変数名を書かないこと。計測していない数値・試行回数を書かないこと。**（ラウンド4で、実在しない関数を前提とした差分と未計測の統計値が出力されたため、明示する）
- 修正コードを提示する場合は、実在する関数に対する差分形式のみ可。全体ファイルの再生成は不要。
- 意図的仕様（上記）に抵触する修正は提案しない。
- 問題が見つからなかった項目は「実測のうえ問題なし」と試行規模を添えて明記する。
