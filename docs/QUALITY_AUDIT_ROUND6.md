## 採否と対応

### R6-01（高・T5）320px幅でヘッダーとステータスが横にはみ出す → 採用・修正済み
- GPT実測: 320×568で header scrollWidth=355、status scrollWidth=338。
- Muse側再測定（現在のコード）: header 353 / status 338 で再現を確認。
- 修正: `@media(max-width:360px)` を追加し、ヘッダー見出し・ボタンのフォントと余白、ステータスのピル余白を縮小。回帰テスト LY1（320pxで scrollWidth ≤ clientWidth）。なお初回の配置はCSSカスケード順（後方の基本ルールと同詳細度）でステータス側が無効化されLY1が失敗したため、メディアクエリをスタイル末尾へ移して解消した。

### R6-02（高・T5/T1）横向き・低画面高で操作パネル下部に到達できない → 採用・修正済み
- GPT実測: 812×375で #stage clientHeight=86 に対し scrollHeight=210、操作時間欄がステージ下端の外。
- Muse側再測定: 812×375で stage 86/258、844×390で 94/258、到達不能を再現。
- 修正: `#stage` の overflow を hidden から `overflow-x:hidden; overflow-y:auto` に変更し、ステージ内スクロールで全操作に到達可能にした（盤面・ヘッダーは固定のまま）。縦向きの標準サイズ（375×667等）では従来どおりスクロールなしで収まる。回帰テスト LY2/LY3。

### R6-03（中・T4）全リセット（旧・設定リセット）でルーレット設定が初期化されない → 採用・修正済み
- コード照合で確認: リセットハンドラは盤面サイズ・落ちコン・目覚め・操作時間等を初期化するが、`roulPreset`／色チェック／間隔には触れていなかった。ラウンド5の「パレット再描画で保持」は意図した仕様だが、全リセットは全設定の初期化が仕様（ボタンの説明文とも一致）。
- 修正: 全リセットでルーレットを標準プリセット・全色・1秒に初期化し、カスタム領域を閉じる。回帰テスト R11。

### R6-04（中・T4）編集配置でルーレットマスに特殊ドロップの潜在型が残る → 採用・修正済み
- コード照合で確認: ラウンド5の変換（bakeRoulEntry）はドラッグ（swapHeld）と落下（applyGravity）とルーレット設置時には入っていたが、**ドロップのペイント配置・一括変更・陣**の3経路に無く、ルーレットを外すと毒等が復活する状態だった（フッターの仕様記述とも不一致）。
- 修正: paint のドロップ配置、一括変更、陣の3経路に bakeRoulEntry を追加。回帰テスト R10。

### R6-05（条件付き・T1）ポインターキャプチャ喪失で掴み状態が残る → 採用（防御的修正）
- GPTの再現はブラウザAPIでキャプチャを強制解放した人工ケースで、通常操作での発生は未検証と明記されている。コード照合: pointerup / pointercancel は処理済みだが `lostpointercapture` の受け口が無かった。
- 修正: `lostpointercapture` リスナーを追加し、キャプチャを失った場合は pointercancel と同等に手を終える（通常の pointerup 後は無動作）。回帰テスト P8。

### R6-06（要件制約・T4/T3）全マス同位相ルーレットではシャッフル後マッチゼロが不可能 → 仕様として受容・明文化
- 全マスが同じルーレットだと、その瞬間の実効タイプは全マス同一色になるため、2色プールではチェッカーボード配置でもマッチを避けられない。グローバル同期という意図した仕様の帰結であり、GPTも同期仕様を壊す修正は推奨していない。
- 対応: 仕様メモ（フッター）に「全マスが同じルーレットで揃っている盤面ではシャッフルしてもマッチが残ることがあります」と明記した。通常盤面のシャッフルはGPT実測2,400回・本スイートSH1ともマッチ残存0。
