# 品質監査レポート ラウンド5（統計的性質・不変条件ファズ）

- 実施日: 2026-11-05
- 監査プロンプト: docs/AUDIT_PROMPT_ROUND5.md（S1 分布統計／S2 不変条件ファズ／S3 競合・タイミング／S4 ダメージ会計の突合／S5 ルーレットの長時間挙動）
- 体制: Muse側で検証項目を先行実施 → ChatGPT（推論 High、新規チャット）に現行版807行を添付して監査 → 全指摘を実コード・実測で照合してから採否判定。

## 1. ChatGPT監査の取り扱いに関する注意（検証結果に影響）

ChatGPTの**チャット本文**は別アプリの監査だった：実在しない関数（resetGame／handleDropClick／attachSwapHandlers／chance／logMoveLog 等、本体に出現回数0を実測）や存在しない概念（誤タップ率・誤解釈ペナルティ・DROP_RATE）を根拠にし、S1〜S5の見出し自体も指示書と異なるものに化けていた。本文中の「実測値」は自己矛盾（実行していないと述べつつ試行回数を主張）しており、**本文と修正パッチ（チャット提示分）は一切採用しない**。

一方、ChatGPTが生成した**成果物ファイル**（監査報告書MD・検証スクリプトと実測JSON一式・修正パッチ）は実コードに基づく本物の監査だった。報告書は見出し・行数を正しく復唱し、実ブラウザ測定の生データ（seed付きJSON）が同梱されていた。以後の指摘検証はこの成果物を対象とし、全件を Muse側で再実測してから採否を決めた。

## 2. GPT成果物の指摘と検証結果（4件すべて実在を確認し修正）

### 指摘1〔高〕2色目覚めのシャッフルで未解決マッチが残る
- GPT実測：初期盤面にマッチを含む割合が各2色プロファイルで 38.97〜40.07%（各3,000盤面）。
- Muse再実測：300回シャッフルで firewater 35.7%、lightdark 41.3%（多めプロファイルは0%）。**再現を確認**。
- 原因：shuffleBoard が旧盤面を残したまま1マスずつ上書きし、wouldMatch が未確定の旧セルまで参照していた。2色プールでは両色とも「マッチする」と誤判定されやすく、再抽選ガード（30回）を使い切ってマッチする色を置いていた。完成盤面の最終検査もなかった。
- 修正：盤面を一旦 null にしてから、確定済み隣接マスだけを見て許可色（プール内の重み付き重複を保持）から選ぶ方式に変更。2色時は完成盤面を findMatches で検証し、不成立なら再配置（最大64回）、最終フォールバックは2色チェッカーボード（構造的にマッチ不能）。
- 回帰テスト：SH1（全プロファイル×80回シャッフル、全てマッチなし＋2色の純度維持）。

### 指摘2〔低〜中〕解決中のポインターダウンで activePid が残留
- コード確認：pointerdown ハンドラーが activePid を代入した後に resolving 判定で return していた。プレイ中はポインターキャプチャを取得する前に return するため、盤面外で離すと pointerup が届かず activePid が残り、別IDの入力が拒否され続けた（通常タッチでは暗黙キャプチャで解消されるため実害は限定的、というGPTの限定も妥当と判断）。
- 修正：resolving／テープの拒否判定を activePid 代入の前に移動。
- 回帰テスト：V3（解決中に合成 pointerdown を注入しても activePid が null のまま）。

### 指摘3〔中〕特殊ドロップのルーレット進入時に火変換が発生しない
- Muse再実測：毒をドラッグでルーレットマスへ移してもタイプは poison のまま（仕様メモの「お邪魔・毒・爆弾がルーレットに入ると火から通常の色順に変わります」に反する）。落下で進入した場合も同様だった。
- 修正：bakeRoulEntry を追加し、ドラッグ進入（swapHeld）・落下進入（applyGravity 後）・編集でルーレットを置いた場合（paint）に、ロックされていない毒・猛毒・お邪魔・爆弾を火へ変換する。マス側の位相（idx）には触れないため、全セル同期は維持される。
- 回帰テスト：R9（ドラッグ進入・落下進入の両方で fire になる）。
- 採用しなかった部分：GPTパッチの位相手術（roul.next と idx の書き換え）はマス側の位相を後続ドロップ用に変えてしまう副作用があるため不採用。変換はドロップ側のタイプのみに限定した。

### 指摘4〔中〕ルーレットのカスタム設定がパレット再描画で初期化される
- Muse再実測：カスタム（色＝毒＋お邪魔、間隔0.5秒）を設定して buildPalettes を呼ぶと {preset:"std", 色＝基本6色, 間隔1秒} に戻ることを確認（ツール選択・一括選択のたびに再描画される）。
- 修正：buildPalettes 冒頭でプリセット・選択色・間隔を退避し、再構築後に復元する。カスタム領域の表示状態もプリセットに追随させる。
- 回帰テスト：P0。

## 3. S1 分布統計の結論（GPT実測を Muse側でも追認）

- 多めプロファイルの出現率は、プール理論値37.5%に対して初期・補充とも **約32.5〜33.1%**（GPT：全12プロファイル×3,000盤面）。マッチ回避を無効化した対照では約37.5%に戻るため、偏りの原因はマッチ回避リロールの系統的効果と確定した。極端な枯渇ではなく実害基準に当たらないため**欠陥扱いしない**。ただし仕様メモの「約4割」という記述は実測と合わないため「出現率は実測で約33%」に訂正した。
- 毒・お邪魔は公称20%に対し初期19.9〜20.0%／補充18.95〜19.16%で乖離は軽微。なし・2色（補充の範囲外色混入は意図的仕様の範囲）も問題なし。補充後に新たなマッチが生じないことも別シードで確認済み（ラウンド4のFZとも一致）。

## 4. 問題なしと確認した項目（GPT成果物の実測＋Muse側スイート）

- S2 不変条件ファズ：ランダム操作420回で例外0・盤面欠損0・表示と内部値の不一致0（GPT）。Muse側 FZ（60解決）・U系テストとも一致。
- S3 競合：解決中の各種リセット／モード切替／サイズ変更は盤面・ターンを変えず、タイマーはリセット後に復活しない。タブ切替・凍結でも時計の破綻なし（実機の visibility:hidden 復帰は未検証という限定付き）。
- S4 ダメージ会計：毒・猛毒・爆弾・トゲの組合せ150ケースで期待%と表示が150/150一致（GPT、Muse側でも式を検算）。トゲの保持ドロップ免除も実測一致。
- S5 ルーレット：仮想時計オフセット12点×3間隔で全セル同期・周期ズレ0、14プリセットの色周期も一致。ロック／保持中の凍結と解決中ラッチも維持（24時間は時計注入シミュレーションであり実放置ではない、という限定付き）。

## 5. 収束判定

ラウンド5は GPT成果物から有効な新規欠陥4件（うち高優先度1件）が見つかり、全件修正＋回帰テスト追加した。修正後の回帰スイートは **58項目・失敗0**（新規 SH1／P0／R9／V3 を含む）。独立再実測でも、2色シャッフルのマッチ率は 35.7〜41.3% → **0.0%**、パレット設定は保持、進入変換は fire を確認。よって**未収束**。ラウンド6は新しい角度（実機・ブラウザ差異、長時間セッション、極端な設定値の隅）で監査を継続する。なお本ラウンドの教訓として、ChatGPT監査はチャット本文ではなく生成ファイル（報告書・実測データ）を正として受け取り、本文のみの場合は監査として数えない運用を明記する。
